# Этап 4: уборка неиспользуемых экранов

Сначала выполни «Общий порядок работы над любым этапом» из CLAUDE.md (раздел «🗺 Дорожная карта»), шаги 1–3. Если этап 4 уже ✅ — остановись.

**Это интерактивный этап.** Ничего не удаляется без явного «да» пользователя по каждому пункту.

## Шаг 0. Проверка срока

Посмотри в таблице дорожной карты дату выкатки этапа 1 («выкачен YYYY-MM-DD»).
- Если этап 1 ещё не ✅ — скажи, что сначала нужен `/roadmap-1-usage`, и остановись.
- Если с даты выкатки прошло **меньше 28 дней** — скажи, сколько дней осталось, и остановись. Данных за меньший срок мало для решений на 5–7 игроков.

## Шаг 1. Данные

Доступа к боевой БД у тебя нет и не нужно. Попроси пользователя отправить боту в Telegram команду `/usage` и вставить сюда весь ответ (он может прийти несколькими сообщениями).

## Шаг 2. Полный список экранов

Составь инвентарь всех экранов по коду, а не по памяти: пройди роутеры в `bot/handlers/*.py` — фильтры `F.data == "..."`, `F.data.startswith("...")`, `Command("...")`. Каждый приведи к той же нормализованной форме, что пишет счётчик (`normalize_action`, этап 1 — числовые сегменты `_<число>` убраны), чтобы сопоставить со строками `/usage`.

## Шаг 3. Таблица для пользователя

Для каждого экрана: нормализованное имя | что это по-человечески (какая кнопка, где) | открытий за 30 дней | разных игроков | твоя рекомендация (**удалить / оставить / спрятать глубже**) | почему.

Не рекомендуй удалять то, что **редкое по природе**, а не ненужное: подтверждения и отмены матчей, ввод результата, боссфайт и всё вокруг трона, админские команды (`/usage`, `/dbstats`, `/backup`, `/myid`, `/fix_rating`), `/start`, `/help`, экраны ошибок. Их помечай «оставить — редкий по природе».

Честно проговори ограничение: счётчик видит только **открытые** экраны. Дайджесты, которые бот шлёт сам (итоги дня/недели/месяца/квартала/года), им не измерить — их этот этап не трогает.

## Шаг 4. Согласование

Жди решения пользователя по каждому кандидату. Если по какому-то экрану пользователь сомневается — по умолчанию «оставить».

## Шаг 5. Удаление одобренного

Для каждого одобренного экрана: хендлер, кнопка(и), ведущие на него (ищи callback_data по всем клавиатурам `bot/keyboards/inline.py` и в хендлерах), тесты этого экрана, упоминания в README.md (список фич), `/help` (`bot/handlers/start.py`), CLAUDE.md. Если у удаляемого экрана есть вспомогательные функции, которые больше никем не используются, — удали и их (проверь грепом). Не трогай данные в БД. Если удаление экрана делает ненужной какую-то ачивку или рекорд — остановись и спроси, это уже не уборка экрана.

## Готово, когда

Тесты и ruff зелёные, релиз выпущен скиллом `release`, в таблице дорожной карты «✅ vX.Y.Z, выкачен YYYY-MM-DD» и одной строкой — что удалено. В CLAUDE.md запиши, что удалили и почему (по данным `/usage` за какой период), чтобы через полгода было понятно, куда делся экран.
