# О файле

Это рабочие инструкции для AI-ассистента (Claude Code) и краткая дока проекта.
Стек: Python, aiogram 3.x, SQLAlchemy 2.x (async), APScheduler.

**Этот файл грузится в контекст ассистента автоматически и целиком на каждой сессии** — это его основная цена в токенах, поэтому он умышленно держится компактным. Закрытые постмортемы (инциденты, которые давно починены и не повторяются) и полностью отменённые/отложенные на неопределённый срок дизайны фич вынесены в `docs/HISTORY.md` — читать его по явному запросу или когда нужно разобраться в конкретном прошлом инциденте, не по умолчанию. Там же — раздел «Архив подробных версий правил»: полный исходный текст пунктов «Бизнес-правил», которые здесь сжаты до текущего состояния (v2.139.2); правила те же, ушла хроника «как к этому пришли». Действующие бизнес-правила (как код работает СЕЙЧАС) остаются здесь целиком, включая обоснование «почему» — это не история, а спецификация.

# Проект

Telegram-бот для рейтинговых игр в настольный теннис внутри закрытой группы.
Регистрация только по инвайт-коду. Один разработчик. Стадия: MVP в проде на VPS (FirstVDS).

**Что умеет бот:**
- Регистрация игроков по инвайт-ссылке (`/start <INVITE_CODE>`)
- Вызов соперника на матч (матч начинается сразу, без шага принятия)
- Внесение результата: пошаговый FSM-ввод или прямой ввод счёта в чат (`11:7 9:11 11:5`)
- Отмена принятого матча любым из участников
- Автопересчёт рейтинга после каждого матча
- Таблица рейтинга (с ▲▼ за неделю), личная статистика, история матчей, личные встречи (H2H)
- **Босс-файт за 1-е место** — #1 занимается не по очкам, только победой над текущим чемпионом (`Player.is_champion`) в отдельном матче: ×2 к дельте, ничья запрещена, блокировка мгновенного реванша, авто-освобождение трона при 7 днях бездействия чемпиона
- Достижения (69 ачивок, 31 скрытая до разблокировки, сгруппированы по категориям на экране «Достижения») + пасхалки после матчей + прогресс до ближайшей счётной ачивки в статистике
- Личные рекорды (7 метрик, сравнение только с собственной историей игрока — не с другими) после матча
- Звания по диапазону рейтинга (Джун/Миддл/Сеньор/Тим лид/Ген дир) — косметика в статистике и профиле
- Зал славы — полная история правлений на месте #1 (кнопка на экране «Рейтинг»)
- Карточка «поделиться победой» — текстовая карточка со счётом и репортажем, кнопка на экране результата (только у реального победителя)
- Постоянная клавиатура снизу — Вызвать на матч / Рейтинг / Статистика, всегда под строкой ввода
- График динамики рейтинга (quickchart.io)
- Тепловая карта активности за 90 дней (личная/клубная, переключатель кнопкой) — экран «Статистика»
- Рекорды клуба, матрица доминирования и индекс формы (кнопки на экране рейтинга) — индекс формы ранжирует по последним 10 матчам, а не по всей карьере
- Экран «Рекомендации» (было «Мои матчи» до v2.124.0 — название путало с личной историей): активные матчи клуба + «С кем сыграть?» с рекомендациями (`get_rec_signal`)
- Только один активный матч на игрока одновременно + напоминание через 24 часа, если матч завис
- Итоги дня каждый вечер в 21:30 МСК (топ дня + «матч дня»)
- Еженедельный дайджест каждый понедельник в 9:00 МСК + итоги месяца 1-го числа в 10:00 МСК + итоги квартала 1-го числа января/апреля/июля/октября в 10:30 МСК + итоги года 30 декабря в 12:00 МСК (сдвинуто с 31.12 14:00 в v2.134.0)
- Голосование «Итоги года: неформальные звания» — раз в год, 21-30 декабря (приглашение → напоминание → закрытие вместе с «Итогами года»), см. этап 3 дорожной карты ниже
- Ежемесячный offsite-бэкап БД админу в личку (1-го числа 10:15 МСК) + `/backup` для бэкапа по запросу (админ)
- `/feedback` — отправить идею/баг напрямую разработчику, доступна всем игрокам

# Бизнес-правила (не нарушать)

- **Результат может внести любой участник матча.** Если репортёр ввёл счёт, где он проиграл, бот инвертирует перспективу и корректно записывает победу соперника (`sets_data` всегда хранится в перспективе победителя; при ничьей — в перспективе challenger).
- **Рейтинг никогда не сбрасывается.** Только накапливается через `+delta` / `-delta` после каждого матча. Пол рейтинга: **1000.0** для новичков (до 15 матчей), **900.0** для ветеранов (15+ матчей). Стартовый рейтинг: 1000.0.
- **Рейтинг отображается с одним знаком после запятой** везде (не `int`, а `round(x, 1)`) — **кроме экрана «Вызвать на матч»** (`players_list_kb` в keyboards/inline.py + заголовок в `challenge.py`, v2.115.0): там сознательно `round(x)` до целого — по прямой просьбе пользователя, десятые на экране со списком соперников были лишним визуальным шумом. Сортировка списка остаётся по НЕОКРУГЛЁННОМУ `p.rating` (`sorted(..., key=lambda p: -p.rating)`), поэтому при совпадении округлённого числа выше в списке всё равно окажется игрок с реально большим рейтингом.
- **Счёт партии валидируется** по правилам настольного тенниса: победитель ≥11 очков с отрывом ≥2. Дьюс: 12:10, 13:11 и т.д.
- **Один активный матч на игрока** (стол один) — единый источник `get_active_match(session, player_id)` (utils.py), используется в: `show_players_for_challenge`/`send_challenge` (прячет занятых из списка и авторитетно блокирует; страхует «Реванш» в обход списка), `show_player_profile`/`show_h2h` (прячут «⚔️ Вызвать», если занят зритель ИЛИ соперник — раньше проверялась только пара между ними, кнопка вела в тупик), `show_my_matches` (занят зритель — кнопок «Вызвать X» нет, инфо-строки остаются).
- **Напоминание о незавершённом матче** (`send_match_reminders`, раз в час, порог 24ч от `accepted_at`/fallback `created_at`) — возвращено в v2.80.0 после того, как «один активный матч одновременно» сделало забытый матч блокирующим ОБОИХ участников (раньше висел незаметно, поэтому напоминание убрали как шум в v2.70.0). Флаг `Match.reminder_sent` шлёт один раз на матч. Сообщение — с кнопкой `busy_with_match_kb` (внести результат сразу / отменить).
- **Активный матч можно отменить** любым из двух участников — оба получают уведомление.
- **Босс-файт за 1-е место** (с v2.84.0). Чемпион — `Player.is_champion` (единственный `True`), не пересчитывается на лету. Чемпион не назначен → фича неактивна (сортировка по рейтингу, без кнопок/уведомлений); `bootstrap_champion` в `init_db()` фиксирует лидера при первом старте (без порога матчей — это фиксация, не передача власти); `UPDATE players SET is_champion=0` — ручной рубильник, а факт «фича активировалась» хранится в `ChampionReign`, иначе бутстрап переизбирал бы чемпиона на каждом деплое. **Претендент** — `get_challenger()`, на лету: не чемпион, рейтинг СТРОГО выше чемпионского, ≥`NEWCOMER_THRESHOLD` (15) завершённых матчей; порог не набран — претендента НЕТ (право не откатывается на следующего). Пара (чемпион, претендент) автоматически становится боссфайтом (`Match.is_boss_fight`) при любом способе вызова. Ничья запрещена (`finish_sets()`, страховка в `confirm_result()`). Дельта ×2 (`BOSS_FIGHT_MULT`), `repeat_multiplier` не применяется. Победил претендент → трон переходит; победил чемпион → не меняется (`confirm_result()`). Реванш пары заблокирован (`boss_fight_rematch_blocked()`), пока НЕЧЕМПИОН пары (текущий, через `get_champion()`) не завершит матч с третьим игроком; отменённый (`declined`) боссфайт блок не включает; проверяется и в `send_challenge`, и в видимости кнопок (`can_challenge` в profile.py/history.py, список/ярлык в challenge.py — иначе кнопка ведёт в тупик). **Авто-освобождение** (`check_champion_auto_release`, часовая джоба scheduler.py): чемпион без завершённых матчей >14 дней (`CHAMPION_INACTIVITY_DAYS`, было 7 — неделя слишком коротка для клуба с редкими перерывами) → трон топу по очкам среди игроков с ≥15 матчей, без боя; кандидатов нет — трон остаётся; цикл пропускается, если у чемпиона сейчас активный матч. Смена `is_champion` — **только через `try_transfer_champion()`** (CAS `UPDATE ... WHERE is_champion=True AND id=<from>`) в обоих местах переноса; если трон уже сменился — перенос тихо отменяется (иначе два чемпиона роняли бы `get_champion()` с `MultipleResultsFound`). Гонка в `send_challenge` закрыта `asyncio.Lock` (v2.135.0).
- **`ChampionReign`** (с v2.85.0) — журнал периодов владения #1: `player_id`, `started_at`, `ended_at` (`None` = текущее правление). Открывается/закрывается вместе с любой сменой чемпиона (`bootstrap_champion`, `try_transfer_champion`). Питает рекорд клуба «Дольше всех лидировал» (`longest_champion_reign()`) и служит признаком «фича когда-либо инициализировалась» для рубильника выше — отдельно от текущего значения `Player.is_champion`, которое можно обнулить руками.

- **Смена статуса матча — только атомарным CAS-UPDATE** (`UPDATE ... WHERE status='accepted'` + проверка `rowcount`) — защита от гонок: двойной тап «Всё верно», отмена vs внесение результата. Собирается из фраз-пулов по факторам: **строгие** — камбэк с 0:2 (`COMEBACK_OPENERS`), марафон 5+ партий (`MARATHON_FRAGMENTS` с `{n}`/`{ord}`), дьюс на решающей (`DEUCE_FRAGMENTS`), апсет ≥20 pts (`UPSET_FRAGMENT_TEMPLATES`); **мягкие** (только если строгие не сработали) — проигранная первая партия, 2:1 впритык, дьюс в не решающей партии (`SOFT_COMEBACK_OPENERS`/`CLOSE_DECIDER_FRAGMENTS`/`MID_DEUCE_FRAGMENTS`), потому что при формате до 2 побед 0:2-камбэк и марафон почти не бывают. Иначе — плоские исходы `BLOWOUT_PHRASES`/`PLAIN_WIN_PHRASES`; ничья — сухая `match_drama_reason()`. Индекс фразы — `_stable_pool_index(seed, salt, pool_len)`: MD5 от `f"{seed}:{salt}"` (НЕ линейное смещение и не CRC32 — они не декоррелируют пулы одинакового размера, разбор в `docs/HISTORY.md`); при расширении пулов перепроверять регресс-тестом на разнообразие. Фразы фиксированные, не LLM; стабильны в рамках матча (индекс по `match.id`).

# Рейтинговая формула

```
E                = 1 / (1 + 10 ^ ((loser_rating - winner_rating) / 400))
base_delta       = 32 * (1 - E)

sets_ratio       = winner_sets_won / total_sets        # 0.6..1.0
pts_ratio        = winner_total_pts / all_pts          # ~0.5..0.85
score_mult       = 1 + 0.5*(sets_ratio - 0.5) + 0.3*(pts_ratio - 0.5)

short_match_mult = 0.75 если len(sets_data) == 1, иначе 1.0   # штраф за 1-партийный матч
newcomer_bonus   = 1.2  если у победителя < 15 матчей, иначе 1.0
repeat_mult      = max(0.5, 1.0 - 0.05 × streak)              # streak — подряд побед над тем же соперником

delta = round(base_delta × score_mult × short_match_mult × newcomer_bonus × repeat_mult, 1)
```

Победитель: `+delta`. Проигравший: `-delta`. Пол рейтинга: **1000.0** (новичок, < 15 матчей) / **900.0** (ветеран).

# Архитектурные решения

- **MemoryStorage для FSM** — сознательный выбор для MVP. При рестарте бота незавершённые вводы результата сбрасываются. Приемлемо для малой группы.
- **DatabaseMiddleware делает commit после каждого хендлера** — хендлеры тоже делают явный commit там, где нужно промежуточное сохранение. Двойной commit безопасен с SQLAlchemy.
- **SQLite в проде** — для небольшой закрытой группы достаточно. При росте нагрузки — миграция на PostgreSQL.
- **Инвайт-код через deep-link** — `/start CODE`. Если `INVITE_CODE` не задан в `.env`, регистрация открыта для всех.
