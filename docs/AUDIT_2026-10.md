## 2. Код и тесты

### 2.1. `app.js` стал большим
1801 строка в одном файле: маршруты, экраны, графики, реакции, память устройства. Ошибки ловятся `node --check` (синтаксис) и ручным превью (поведение). **Предложение:** разделить на ES-модули без сборщика (`<script type="module">`): `core.js` (api, кэш, роутер), `charts.js`, `screens/*.js`. Браузер Telegram модули поддерживает; со сжатием и вечным кэшем лишние файлы почти ничего не стоят. Делать вместе с п. 2.2.

### 2.2. Логика фронтенда не покрыта тестами
Python-часть покрыта плотно, а у JS проверяется только синтаксис. Чистые функции (склонения `matchesWord`, разбор чисел в `countUp`, `routeJobs`, подсчёт уровней ячеек) легко проверить в Node без браузера. **Предложение:** `node --test` на 10–15 случаев в задаче lint. Это закроет класс ошибок «экран сломан, а pytest зелёный».

### 2.3. Широкие `except Exception`
27 мест. Почти все осмысленные: сбой рассылки одному игроку не должен валить остальным, фото не должно ронять экран. Проверено выборочно, проблем не найдено. Правило на будущее: `except Exception` только с записью в лог.

### 2.4. mypy
66 ошибок, проверка информационная (`continue-on-error`). Число не растёт с новыми модулями приложения (они типизированы). Отдельная задача не нужна; можно чинить попутно.

### 3.1. Что дал v2.172.0

| Что | До | После |
|---|---|---|
| app.js | 80,9 КБ | 21,0 КБ |
| app.css | 29,8 КБ | 7,6 КБ |
| icons.svg | 15,5 КБ | 3,8 КБ |
| Главная (`/api/home`) | 12,5 КБ | 1,9 КБ |
| Ачивки | 23,6 КБ | 2,7 КБ |
| Первый запуск (без шрифта) | ~139 КБ | ~34 КБ |
| Запросов при повторном запуске (статика) | 4 перепроверки | 0 |
| Ожиданий сети до первого экрана | `/api/me`, потом данные | одновременно |

**Реальное время у игроков — замерить владельцу.** Приложение пишет в журнал сервера время загрузки первого экрана. v2.172.0 выкачен **14.10.2026 около 05:22 МСК** (02:22 UTC). Выгрузка из PowerShell:

```powershell
ssh root@<адрес-сервера> "journalctl -u bottennis --since '2026-10-01' --no-pager | grep 'Mini App: загрузка'" > boot_ms.txt
```

Строки до 14.10 05:22 МСК — «до», после — «после». Сравнивать медиану, не среднее: один медленный запуск по мобильной сети сильно сдвигает среднее. Учесть, что журнал может быть в UTC.

### 3.2. Профиль — следующий кандидат
На 2400 матчах профиль собирается за 179 мс и растёт линейно с историей: каждый раз пересчитывается вся статистика игрока. Сейчас незаметно (в проде истории меньше, ответ сжат и кэшируется на минуту). **Предложение, когда понадобится:** кэш статистики в памяти по `(player_id, id последнего матча)` — сбрасывается сам при новом матче. Не делать заранее.

### 3.3. Лента
30 дней — 16 мс на 600 матчах; «Показать ещё» пересчитывает ленту целиком и берёт срез. При текущих объёмах это дешевле, чем хранить курсор. Пересмотреть, если лента вырастет до 90 дней.

## 4. Безопасность

### 4.1. Нет ограничения частоты для POST
`/api/track` и `/api/match/{id}/react` не ограничены по частоте. Писать может только зарегистрированный игрок с действующей подписью Telegram, и записи маленькие. Для закрытой группы риск низкий. **Предложение:** простой лимит в памяти (например, 30 запросов в минуту на игрока, сверх — 429) — если когда-нибудь вход откроют шире.

### 4.2. Нет Content-Security-Policy
Страница не выполняет чужой HTML: имена вставляются через `textContent`, внешних скриптов — один, `telegram-web-app.js`. CSP добавила бы второй рубеж: `script-src 'self' https://telegram.org`. Нельзя ставить `X-Frame-Options: DENY` — Telegram Web открывает приложение во фрейме; при добавлении CSP разрешить фрейм для доменов Telegram Web (`frame-ancestors`, актуальный список доменов сверить перед включением). Низкий приоритет, проверять на всех клиентах Telegram.

### 4.3. Что в порядке
- Подпись `initData` проверяется на каждом запросе, срок 24 ч.
- Экран «Использование» для не-администратора отвечает 404 — не обнаруживается.
- Ответы API — `no-store`, `nosniff`, `no-referrer`.
- В публичном репозитории нет имён игроков, адресов серверов и ключей; деплой-ключ отдельный, в секретах GitHub.

## 5. Эксплуатация

### 5.1. После деплоя не проверяется само приложение
Job `deploy` проверяет, что сервис активен, но не что веб-часть отвечает. **Предложение:** после рестарта `curl -fsS http://127.0.0.1:<порт>/ | grep -q 'static/app.js?v='` — одна строка, ловит падение веб-сервера при живом боте.

### 5.2. `aiohttp` не закреплён
Веб-сервер приложения целиком на `aiohttp`, но в `requirements.txt` его нет — версию определяет `aiogram 3.14.0`. Обновление `aiogram` может незаметно поменять `aiohttp` (в нём бывают изменения в сжатии и статике). **Предложение:** закрепить в `requirements.txt` ту версию, что стоит на сервере (`.venv/bin/pip show aiohttp`; локально — 3.10.11); обновлять осознанно, с прогоном тестов.

### 5.3. Время в CI
Урок 14.10: прогон, начавшийся в 00:00 МСК, уронил 6 тестов с событиями «N минут назад». Исправлено в v2.170.1, правило — в соглашениях CLAUDE.md. Новые тесты с «сегодня» берут якорь `msk_day_start() + 1 ч`.

### 5.4. Заморозка
Релизы — до 15.12. Голосование «Итоги года» стартует 21.12; репетицию (`/rehearse-year-vote`) провести до заморозки, если менялись `year_vote`, `scheduler` или `middleware`.
